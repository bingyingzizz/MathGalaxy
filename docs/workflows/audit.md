# 工作流：数学审计（audit）

> 触发：用户要求审计/复核/验证数学内容；修复后的独立验证；翻译流水线转来的源文问题；新增/修改工作流要求的复审。
> 判据全部来自 [content-quality.md](content-quality.md)；本文只写**怎么审、怎么记、怎么算完成**。历史失败机制见 `docs/audit-investigation-task2.5.md`（§5、§6）。
> 默认**增量**进行（先分诊历史候选，再审）；未获授权不发起全站语义审计或批量数学修复。

## 1. 输入与必读

- 用户授权的范围（节点/边/星团/问题 id 集）与**是否只读**。明说「只读」的调查必须保持只读（不改源、不 build、不发布）。
- `docs/workflows/content-quality.md`、`docs/audit-register.md`（问题登记簿）、`docs/source-review-register.md`（翻译侧转来的源文问题）。
- 历史记录：`_audit/`（不入 git、不可恢复，**不得删**，不得整本读进上下文，用 `rg`/脚本取摘要）；`_audit/问题清单-v2-2026-11-03.md` §24 的去重候选集是**候选，不是已确认错误**，也不得丢弃。

## 2. 范围（审计单位 = 数学对象 + 其关系）

1. 目标节点及**全部**相关内容字段：陈述、Notes、标题/副标题、`aka`/别名、refs、边上的证明。
2. 入边/出边、端点节点、**完整超边前提**。
3. 相关上游/下游数学依赖。
4. 星团与学科语境。
5. 全图候选检索：语义重复、推广、特例、类比（用 `mg find/show/path/deps/impact/cluster`，**不要**把 `graph.json` 或 `dist/nodes` 读进上下文）。

**覆盖规则（针对 Task 2.5 的覆盖缝）**：专项审计可以按类别拆分，但**合起来必须覆盖第 1 条里的每个字段与第 2 条里的每条关系**。开审前写出本次的覆盖矩阵（对象 × 字段/关系 × 由哪一遍审），空格不得留着当作「通过」。尤其：**Notes 里的证明必须有一遍审**，不能因为「证明归边」就跳过它；边证明审计不得假设 Notes 无关。

## 3. 流程

```
范围与授权 → 源版本 → 找回历史记录 → 抽取数学上下文 → 确定性检查
 → 语义/数学复审 → 核实发现 → 登记 → 授权修复 → 独立验证 → build → 发布与关闭
```

1. **范围与授权**：写下范围、是否只读、预算（见 §5）。
2. **源版本**：记录 `git rev-parse HEAD`、工作树是否干净（含**未提交改动**）、被审节点/边的内容指纹。**确认抽取读的就是想审的版本**：`mg.mjs`、`dist/graph.json` 是**生成物**，可能落后于 `src/data/`（未 build、未提交的改动不会出现在里面）；先比对生成物与源的新旧，必要时在隔离副本里重建，**不得静默审计陈旧的生成数据**。审计结果**只对这个版本有效**（§7）。
3. **找回历史**：先 `rg` 登记簿与 `_audit` 里与目标 id 相关的条目；能复用就复用，不重复同类审计。
4. **抽取上下文**：用脚本拉出目标 + 邻居 + 超边前提。**被审的数学论证本身必须完整给审阅者**——相关的完整陈述、完整证明与必要前提（含 Notes 里的相关论证、超边的全部前提）一字不压缩；**只压缩无关的上下文**（别的节点、与本论证无关的旁注），不要把被审论证本身摘要化。
5. **确定性检查**：`bun tools/_katexcheck-all.mjs`、`xlinkcheck`、`clustercheck <团>`、`_proofaudit`（只给候选）。结果记为 `structural`/`heuristic`，**不是数学结论**。
6. **语义/数学复审**：见 §4。必须评估**完整的相关数学论证**；**不得**把审计缩成检查某些词句是否出现。写出对象类型（content-quality §1 的表）。
7. **核实发现**：每条发现都要有可复跑的证据（引用原文片段 + 数学理由）。模型的自信不是证据。核不实的标 `UNCERTAIN`，不能当 `confirmed`。**源文错误若同时影响英文译文，按 [translation](translation.md) §2 同步登记到 `docs/source-review-register.md`（登记后译文流水线自动搁置该身份）。**
8. **登记**：写入 `docs/audit-register.md`（§6）。
9. **授权修复**：普通审计可修**已核实的局部错误**；节点删除/合并、重大重构、改边语义、改全局组织原则**须先批准**；走 [content-edit](content-edit.md)。
10. **独立验证**：见 §8。
11. **build 与发布**：build 与各道门；commit/push/发布按既有授权，不由审计自动触发。
12. **关闭或记明推迟**：给出状态与理由。

## 4. 模型分工

- 确定性活 → 本地脚本。常规语义/数学**初筛**（thinking 开）→ DeepSeek（`tools/llm/`；目前**没有**面向「Notes/边证明数学审计」的适配器——这是新任务类型，先复用 `semreview` 与流水线，确有必要才加适配器，计费前先 `plan`）。
- **复杂证明、有争议的数学、初筛报出的例外与未决发现 → Claude 或用户。**
- DeepSeek 只收公开数学内容；初筛结果是**线索**，必须回读核验。预算见 `AGENTS.md` §0（单任务 ≤ $0.50、每日 ≤ $2.00，不得拆分绕过，超出先请示）。

## 5. 审计记录必须包含（模型审计的可追溯性）

每次语义审计的记录（写在登记簿条目或随附的 `_audit/` 记录里，并在登记簿里指向它）至少有：

| 字段 | 含义 |
|---|---|
| 被审源版本 | `git` 修订 + 对象指纹 |
| 范围 | 对象 id、字段、关系（与覆盖矩阵一致） |
| 模型与推理配置 | 例：`deepseek-flash, thinking on`；`reasoning effort`。**历史记录只有 `reasoning effort: none` 这一事实，不能据此推出它导致了失败**（Task 2.5 §5/§6 标为假说）。 |
| 方法 | 脚本/模型/人工；提示词版本；是否读了 Notes 与超边前提 |
| 结果 | `PASS/FAIL/UNCERTAIN/N/A` + 发现列表 |

四个**不同**的度量，**必须分栏报告，不得混为一个「完成率」**：**审计覆盖**（审了哪些）· **检出问题**（候选）· **已确认错误** · **已完成修复** · **已验证正确**（独立复核后）。

## 6. 问题生命周期（`docs/audit-register.md`）

每条问题一行，沿用并扩展既有记录，不另起炉灶。**典型路径**：

`detected` → `confirmed` | `rejected` → `repair-planned` → `repaired` → `verified` → `built` → `published` → `closed` | `deferred`（须写原因）

- 状态**可以回退**：`repaired` 的验证失败 → 退回 `repair-planned`（记 `verification-failed`）；`closed`/`verified`/`rejected` 的条目发现新证据 → **重开**（`reopened`）；`deferred` 可随时恢复。每次状态变化追加一行历史（日期、原因、证据）。
- **历史证据不可变，当前状态可变**：登记簿里原始的发现描述、源版本与证据**不得改写或删除**；状态变化只追加，「当前状态」取最后一条。被驳回的发现保留并写明驳回理由。
- 每条必须有：稳定 id、对象 id/字段、来源（历史条目/本次发现）、被审源版本、复核状态（谁/什么方法）。
- **两个不同的维度，不要混写**：**证据溯源**（这条断言从哪来、核到了什么程度：`verified-by-source` 已对源/源码核实 · `reasoned` 数学推理未对外源 · `hypothesis`）≠ **数学有效性结论**（`confirmed`/`rejected`/`UNCERTAIN`）。「对源核实过」说明的是证据来源，不等于该数学断言成立或不成立。
- 历史候选（上述候选集与 Task 2.5 列的线索）**导入时一律为 `detected`**，不预设有效，也不丢弃。分诊战役中先按本节推进，**不重做**历史上的整站审计，也**不批量分诊**。
- 已被登记的、范围外的历史问题**不自动阻塞**无关的增量发布（见 [content-edit](content-edit.md) §6）；本次范围内的**严重**问题必须修复或带准确状态明确推迟；**不得引入新的已确认数学错误**。

## 7. 增量有效性

- **仅当**相关数学输入未变（定义、陈述、证明、前提集、记号约定、依赖）**且**当时的覆盖与验证质量仍然够用时，才可复用历史审阅。**文本没变本身不够**：历史审阅若没覆盖 Notes、只核字句、或在 `reasoning effort: none` 下只审一类问题，就不能当作对整段论证的验证（这是 Task 2.5 的核心教训）。
- 任一输入变 → 受影响结果需重审，**即使证明文本本身没变**（例如它依赖的定义被改了）。
- 偏好增量验证与候选检索，不做重复的全站语义审计。

## 8. 修复后的验证（核心规则）

修复**不是**「请求的句子改了」。必须**重新评估整个受影响的数学论证**：类型、假设、逻辑依赖、中间步骤、结论；并检查受影响的 Notes、标题、证法变体、边说明、refs、译文、下游结果。

- 独立验证者读的是**修复后的内容本身**，不是上一轮的问题清单；**也不被上一个模型的 PASS 判断锚定**——不把上一轮的结论、措辞或「已修」说法当前提喂给验证者，让它从完整论证出发独立评估。
- 记录验证方法与证据。**第二个模型的回答不是形式保证。**
- 历史反例：Lambek 的复核核对「`K⊗M→R^n⊗M→…` 这一句是否出现」而不是整段是否自洽（Task 2.5 §3.2）。

## 9. 保持不确定性（不得自动接受外部结论）

以下在记录里**保持原状态**，不要因外部评审或 Task 2.5 报告的措辞而改判：

- 同一定理的多种真正不同的证明是合法的。
- Lambek 边证明的剩余数学有效性**未**完全确立。
- 评审所称 `thm.metric-compact-equiv` 缺完备性条件，**在现行源文里未复现**（搬迁前 Notes 未核）。
- 紧生成空间的「余极限万有」（`cor.cg-exponential-adjoint` 一线）**未裁决**。
- Le Stum 的归属有证据支持，**本身不是已识别的错误**。

## 10. 工具

`mg.mjs`（查图）· `_proofaudit.mjs`（证明位置**诊断**，正则启发式候选，**不是严格的上界或下界**）· `_katexcheck-all.mjs` · `xlinkcheck`/`clustercheck`/`idstable`/`searchcheck`/`doccheck` · `hygiene.mjs`。**复用，不另建验证系统。**

**`tools/llm/review2.mjs` 不是数学审计**：它只审**译文相对中文源文的忠实度**（thinking 开的译文初筛，且把中文源文当作正确的前提）。它通过 ≠ 数学正确；数学审计是本工作流，目前没有对应的 DeepSeek 适配器。

## 11. 受保护的不变量

`_audit/`、`_pdf/`、`formal/` 不删；不改数学语义约定（Rng 含幺否、Top 是否笛卡尔闭等，待拍板见 STATUS）；不为过门删 `status:'skeleton'`；不改基准去骗门；不动 `src/core/` 与 perfguard。

## 12. 验收与完成条件

- 覆盖矩阵无空格；每条发现有证据等级与状态；五个度量分栏；记录含源版本与模型/推理配置。
- 确定性检查结果标明是 `structural`/`heuristic`，没有被当成数学结论。
- 若有修复：已按 §8 独立验证，并跑了 [content-edit](content-edit.md) 的 build 与门。
- `git status` 无意外改动；临时物按 `AGENTS.md` §7 清理；`docs/audit-register.md` 与 `docs/STATUS.md` 已更新。

## 13. 失败与升级

初筛与确定性手段都定不了 → `UNCERTAIN`，升级 Claude/用户并写明缺什么；源文数学错误 → 登记并走 content-edit，**不在翻译里悄悄修**；预算将超 → 停在 `plan`，请示。

## 14. 发布边界

审计本身不 commit/push/发布。审计产生的内容修复遵守 `AGENTS.md` §9。
