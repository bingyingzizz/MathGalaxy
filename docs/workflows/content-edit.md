# 工作流：修改既有内容（content-edit）

> 触发：修数学错误/不一致；按审计登记簿修复；订正陈述/证明/边/标题；拆分、合并、删除节点；改星团归属。
> 判据来自 [content-quality.md](content-quality.md)；发现与验证来自 [audit](audit.md)。

## 1. 流程

```
识别问题 → 核实证据 → 分析受影响的数学与工程依赖 → 改**权威源** → 同步受影响字段
 → 重审 → build → （获授权才）发布
```

1. **识别 / 核实**：问题必须在 `docs/audit-register.md` 里有一行且证据核实过（至少 `confirmed`）；没核实的不要「顺手修」。
2. **分析依赖**：用 `mg show/deps/impact/path` 看上下游与全部出入边（含超边前提）；列出受影响字段（§2）。
3. **改权威源**：只改 `src/data/`（`packs/*.js` 中文真源；`i18n/*.en.js` 旁挂英文）；生成物（`dist/`、根目录 `llms/policy/reading/notation/alias`、站点页）**只能通过改真源或生成器再 build 得到，不得手改**；叙述性生成文本要改其模板/生成器。
4. **同步字段**：见 §2；**不机械重写不受影响的字段**；**不得在别的字段里留着被取代的错误内容**（这正是 Goldstine/Lambek 的机制：Notes 与边各有一份证明，只改了一份）。
5. **重审**：只做 [audit](audit.md) §8 这一步——重新评估**整个受影响的数学论证**，不是核对「那句话改了没」。这是**指针**，不是把整个 audit 工作流重新开一遍；build 只在第 6 步跑一次。
   **相称原则**：不涉及数学语义的琐碎编辑（错别字、标点、排版、纯文档）只需相关的门，不需要重审与登记；实质性的数学改动才走完整流程。
6. **build 与门**：`bun tools/build.mjs`（⚠ 有副作用；先在隔离副本验证）→ `_katexcheck-all` → `doccheck --strict` → `searchcheck`（改基准必须写理由并经批准）→ `idstable`（干跑）→ 视情况 `xlinkcheck`/`clustercheck`。
7. **发布**：不自动；按 `AGENTS.md` §9。
8. **登记**：把阶段推进到 `repaired → verified → built`，写证据。

## 2. 一处数学更正要同时考虑的字段

陈述与 Notes · 标题/副标题 · 边证明与证法变体 · 边说明 · 定义引用 · 构造依赖（黑/粉、层）· 下游结果 · **中文与英文**（译文以源哈希追踪：中文改了，英文必然 stale，需走 [translation](translation.md) 重译；**不要手改英文去追中文**）· 生成页与 AI 检索数据 · 搜索基准。

**失效规则**：相关数学输入变化（定义、前提集、记号、依赖）时，使**审计记录与译文记录**失效或重查，**即使证明文本没变**（audit §7）。

## 3. 结构性修改（拆分 / 合并 / 删除节点、重构星团）

**须先获用户明确批准**（`AGENTS.md`「agent 权限」）。批准后：检查既有关系、别名、深链、译文、用户状态兼容性（`idstable`）、生成物；id 保持稳定，必须变更时登记退役。不得在批准前「先改了再说」。

## 4. 受保护的不变量

不删数学内容、审计记录、`_pdf/`、`formal/`；不改数学语义约定；不改 `src/core/`（那是 [engine](engine.md)）；不改基准去骗门；`status:'skeleton'` 不为过门而删；`packs/*.js` 不批量格式化；不 `git add -A`。

## 5. 验收与完成条件

- 受影响字段**全部**已同步（§2 逐项勾对），无被取代的旧内容残留。
- 重审结论按 audit §8 记录；登记簿状态与证据已更新。
- 门全绿；`git status` 无意外；临时物清理；STATUS 更新。

## 6. 增量发布政策

已登记、范围外的历史问题**不阻塞**无关的增量发布；**本次范围内的严重问题**必须修复或带准确状态明确推迟；**不得引入新的已确认数学错误**。commit/push/发布仍需明确授权。

## 7. 失败与升级

重审不通过 → 退回 `repair-planned`，不得带着「已修」的说法收工；数学上有疑问 → 标 `UNCERTAIN` 升级；需要结构性修改 → 停下请示。
