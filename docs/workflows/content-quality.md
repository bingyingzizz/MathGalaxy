# 数学图质量标准（共用；所有内容类工作流引用本文，不各自重定义）

> 适用：审计（[audit](audit.md)）、新增（[content-add](content-add.md)）、修改（[content-edit](content-edit.md)）；PDF 内容在并入前必须满足它（[pdf-ingestion](pdf-ingestion.md)）；译文只引用其中 §14（[translation](translation.md)）。
> 本文只写「什么算对」。**怎么做**在各工作流；**边的语义与 schema 的实现细节**以 `src/core/graph.js`、`README.md`/阅读指南与 `docs/content-guidelines.md` §3.4 为准，本文不重复、不改写。
> 规则的来源等级见 `AGENTS.md`「规则的权威等级」。本文里每一节都是**数学正确性要求或用户已拍板的准则**；凡数字都只是诊断（§10、§11）。

## 0. 判定词与通用约定

- 结论只用 `PASS` / `FAIL` / `UNCERTAIN` / `N/A`。不确定的数学判断记 `UNCERTAIN` 并写明缺什么；**不要为了好看压成 PASS/FAIL**。
- `build 绿`、`katex 绿`、「没有诊断旗标」**都不是数学正确的证据**（§1）。
- 审计的单位是**数学对象及其关系**（节点 + 全部字段 + 入边/出边 + 超边完整前提），不是孤立的文本字段。
- 任何数字（度数、星团大小、证明条数……）只能触发调查，**不得决定数学组织，更不得为凑数造关系**。

## 1. 数学正确性

逐字段检查：定义、陈述、假设、量词、结论、证明、Notes、标题/副标题、边说明。找：缺假设、无效蕴含、无依据的推广、逻辑缺口、循环论证、无支撑断言、**数学类型错误**、同一结果在不同字段里不一致。

适用时**必须写出每个对象的类型再核对**（这是 Task 2.5 的核心教训）：

| 要显式核对 | 典型错误（实例见 `docs/audit-investigation-task2.5.md`） |
|---|---|
| 定义域/值域、谁作用在谁身上 | Goldstine：$\xi\in X^{**}$ 作用在 $X^*$ 上，却写成 $\xi(x_j)$，$x_j\in X$ |
| 对偶配对 | $(X^{**},w^*)^*$ 误写成 $J_X(X)$ |
| 左/右模 | Lambek：把右模的 $R^n$ 满射到左模的子模 |
| 伴随方向、左/右伴随 | `thm.top-cond-adjoint` 方向反 |
| 极限/余极限、反射/余反射 | `thm.stone-profinite` 写成余极限 |
| 存在、唯一、典范构造、任意同构 | 不要把「存在某个同构」写成「典范同构」 |

## 2. 存在性与构造

- 用公理、性质、泛性质**定义**一个对象是合法的；但**定义本身不证明存在**。
  - 例：定义「完备有序域」合法；仅断言「实数构成完备有序域」而无构造/存在定理，存在性义务未解决。
  - 例：用泛性质定义张量积合法；代表对象的存在必须另有论证。
- 存在性可来自公认的基础公理、显式构造或有效的存在定理；**非构造性存在证明合法**。
- 检查：存在、良定义、必要的唯一性、基础依赖。不要默认熟悉对象存在。
- 构造图应当反映「对象及其性质是怎样被建立起来的」。
  （用户的「每一层都从上一层构造出来」见 `docs/content-guidelines.md` §3.2；其中旧的绝对禁令措辞已被本节取代。判据：**要求存在性被建立，不禁止公理/泛性质刻画**；公开策略 `policy.md` 已同步。）

## 3. 定义引用

检查定理陈述与实质数学内容里**直接使用**的概念，是否有对应的 `definition` 引用：

- 缺失、虚假/无关、重复、指错目标、指向不恰当的特例、缺前置定义、文字与图关系不一致。
- 例：定理明文使用复数，则必须有指向复数定义的引用。**合法的基础节点可以没有入边的 definition**；不存在「必须有入边」「最少连接数」的要求，孤立/无入边只是调查候选。
- **不要**为了增加连通性递归补每一个间接祖先。
- 区分四件事：定义引用 / 证明依赖 / 类比关系 / 文献引用。用现有 schema 与边方向，不自创。

## 4. 逻辑关系与证明依赖

检查相关入边/出边、端点与**完整超边前提**：

- 所述关系是否真成立；蕴含方向；等价的**两个方向**；超边前提是否充分；有无缺失/多余前提；
- 声明的前提 vs 证明实际用到的结果是否一致；周边关系是否有效；有无假/冗余/误导边。
- 证明需要 A、B、C **联合**成立，不得拆成三条单前提蕴含。
- 证明里用到的有数学分量的结果必须出现在依赖里；普通代数变形、初等逻辑步骤**不需要**人为立节点。
- 缺的关键前置：在范围内就走 [content-add](content-add.md) 补上，否则在审计登记簿里登记为未解决依赖。

## 5. 黑边、粉边与构造层

沿用项目既有语义，**不得自行重新解释边类型**：

- **黑色** implication = 主要的数学构造依赖。
- **粉色** implication（`layer:false`）= 补充的有效推论/备选证明路径，**不参与分层**。
- definition / equivalence / analogy 保持各自既有含义。
- 实现以 `src/core/graph.js`（分层算法）、渲染器与阅读指南为准；本节只规定**怎么审**，不重述实现。

要问的：黑边是否构成连贯的构造体系；必要构造依赖是否被误标粉；补充性的高阶证明是否被误标黑；构造环是否有数学依据；SCC 缩点是否掩盖了无效的依赖环；算出的层是否与真实构造前提一致。

- 例：某定理**唯一**的构造性证明用了复积分，则它不能在复积分前置之前被当作已建立；若已有独立的初等构造，用复积分的高阶证明可用粉边。
- 允许多条**独立**的黑色构造路径。**不设「单黑边」规则。**
- **层号是派生结果，不是改变数学关系的理由。** 层异常时分清三种来源：缺数学依赖 / 边分类错 / 算法缺陷。
- ⛔ 不为了图好看改层或改边色。

## 6. 证明归属、完整性与重复

- 蕴含的完整证明属于相应的**逻辑边**；Notes 放解释、出处、限定、例子、数学语境，不是完整蕴含证明的存放处。
- 检查：Notes 里残留的完整证明；**没有文字标记的隐藏证明**；被取代/错误的证明仍作为现行内容；同一证明在多字段的冗余拷贝（含与边**不一致**的拷贝）；无数学区别的重复边；每个证明与其前提集是否一致。
- **保留真正不同的有效证明方法**。不设「每个定理一份证明」。前提集不同可分边；前提与结论都相同时，优先用既有的「同一条边多证法」机制。
- 区分状态：缺失 / 骨架 / 完整 / 已核验 / 有争议 / 过期——记在既有记录里（`status:'skeleton'`、审计登记簿）。**不得为了改善覆盖统计去掉未完成标记。**
- 证明检测在确定性手段不够时**需要语义判断**。`∎`/「证明」等标记只能给候选（`tools/_proofaudit.mjs`），不能证明语义上完整或不存在。

## 7. 节点粒度与语义去重

检查：独立概念被并成一个节点；一个连贯概念被无谓拆碎；等价的定义/结果以重复节点存在；独立命题/推论藏在不相干的 Notes 里；节点类型是否描述其数学角色；名字/别名/检索词是否指向正确的概念。

- 不止看直接邻居：做全图候选检索找语义重复（`mg find` + 别名 + 陈述比对）。
- **相同术语 ≠ 数学等价。**
- 粒度跟数学意义走，不跟任意计数或教材编号走。

## 8. 推广与特例

找已有的推广与特例：节点是否是另一节点未标注的特例；已有特例缺与一般结果的关系；平凡/冷门特例是否无谓重复一般定理；更一般的结果能否改善组织。

- **保留**经典的、常用的、有教学价值或独立价值的特例。**不因存在更一般定理就自动删特例。**
- 合并/删除只在数学上有理据时**提议**，**破坏性重构须先获批准**。

## 9. 类比与跨学科关系

主动调查有意义的类比、对偶、共同泛性质、跨领域对应；检查已有 analogy 边的数学准确性；在授权范围内补确有理据的缺失类比。

- ⛔ 不因术语相似建类比边；⛔ 不把类比表示成逻辑蕴含。**同词不同物只需要消歧注，消歧与数学类比是两回事。**

## 10. 例子与反例

按真实的数学与教学价值评价：是否正确说明目标结构、区分数学性质、展示重要构造、或确实反驳所述命题。

- **没有「例子必须有 ≥ N 个邻居/边」的要求**（用户 2026-11-24 明确否决旧的「例子须 ≥ 2 条强边」判据；`tools/clustercheck.mjs` 已移除相应旗标）。
- ⛔ 不为满足图密度目标编造连接。「薄接线」列表只是调查线索。

## 11. 星团与学科组织

检查：学科/星团归属；每个团的数学连贯性；团名与描述；缺失的核心定义与重要中间结果；不相干主题混放；过度碎片化；大而不连贯的团；是否值得拆分/合并；跨学科摆放与图的可读性。

- 团大小、连通度等统计**只作诊断信息**，不能代替数学判断。
- **不执行未经授权的数字阈值**。历史上的「一个团别超 40 点」没有用户原话出处、与用户拍板的「内部密无所谓」矛盾、也没有任何门检查它，现已降为诊断信息（公开策略已同步）。
- 重大重构须批准。

## 12. 记号与术语

维护并遵守既有记号指南（`notation.md`，生成物；真源 `src/data/notation.js` 一类，以 build 为准）。跨陈述、Notes、证明、边说明、译文检查。

特别留意：内积线性约定、曲率符号、左右模约定、链/上链分次、复合方向、Fourier 归一化、集合论与范畴论记号。区分无害的记号差异与**不相容的数学约定**。导入的记号要规范化，**不得悄悄改变数学内容**。

## 13. 文献与出处

核对作者、书名、版本、定理编号、页码、来源归属；找伪造/错误/重复/无依据的引用。区分：原文陈述 / 原文证明 / agent 补写的证明 / 对原文的订正 / 补充文献。

- 教材来源的内容看似有误：有原书就查原书，否则给出严格的数学论证。**模型自信不是证据。**
- 无法取得或未核实的来源要**明说**记录（见 `docs/audit-investigation-task2.5.md` §8 的写法）。
- `refs` 只写真实教材/论文；用户讲义、PDF 页、日期只进 `_audit`（`AGENTS.md` §4）。

## 14. 中英一致

检查：数学等价；术语准确；假设、量词、否定、蕴含方向保留；公式记号一致；已支持的译文字段齐全；内部引用正确；图关系语义保留；译文状态与源版本一致。

- **源文正确性与译文忠实是两件事。** 忠实译出错误的中文陈述**不通过**数学审计。
- ⛔ 不通过英文译文悄悄修中文数学；源文问题走 [audit](audit.md)/[content-edit](content-edit.md)（翻译侧登记在 `docs/source-review-register.md`）。

## 15. TeX 与呈现

复用确定性检查：KaTeX 语法、定界符、不支持的命令、转义错误、未解析的内部引用标记、断链、生成标题/文本里的公式丢失、中英公式对应（`bun tools/_katexcheck-all.mjs` 等，见 `docs/tools-and-methods.md`）。必要时做针对性的浏览器检查。

- 保留既定的呈现决定，包括**可接受的横向滚动长公式**（用户 2026-11-02 裁定「公式溢出无所谓」）。
- 不把无害的呈现偏好变成强制限制。

## 16. 图完整性与产出一致

检查：稳定 id、重复身份、悬空边、无效引用、依赖环、受影响的生成物（`idstable`、`xlinkcheck`、build 内断言）。

确保适用的产出对应同一份数学源：交互图、中英静态页、Markdown、JSON、证明/Notes 分页、搜索索引、AI 检索接口。

- 缺证明、孤立节点、异常的星团归属是**候选**，不自动是错误。
- 生成物只能通过改**真源或生成器**再 build 来变，不得手改（见 [content-edit](content-edit.md)）。
