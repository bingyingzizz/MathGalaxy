# 工作流：PDF 摄取（pdf-ingestion）

> **现状（如实）**：**操作化的 PDF 流水线尚未实现**（路线图 Task 4；设计预留见 [`docs/llm-pipeline.md`](../llm-pipeline.md)「Task 4 预留设计」）。本文把**已验证过的手工做法**与历史工具整理成规程，供 Task 4 复用，**不声称下列未实现的能力已可运行**。⛔ 不重新发明识别系统；不装 Ollama/CUDA/MinerU 等大依赖，除非另行批准。

## 1. 阶段（互相分离，各有自己的记录）

```
文档登记 → 提取或逐页识别 → 数学转写 → DeepSeek 订正 → 存疑区域核验
 → 结构化候选抽取 → 数学审计 → 内容新增（content-add）
```

**原始转写、数学订正、最终图组织在逻辑上必须分开**：后一阶段只读前一阶段**已通过**的记录；不得用最终组织覆盖原始转写。

## 2. 方法选择：优先文字层，必要时目视核验

**有可靠文字层的 PDF（电子版）优先直接提取文本**，不要先跑图像识别；只有当数学内容的提取**不完整或已损坏**（公式乱码、符号丢失、版面错乱）时，才对**有问题的页/区域做有针对性的目视（视觉）核验**，并把核验结果与文字层提取并存记录。扫描件/手写件没有文字层，才走下表的图像识别路线。

## 3. 历史方法（有文档记载）与当前已验证的能力

**下表是文档记载的历史方法**，不是本次核实过「现在可用」的能力：`_tools/` 里的脚本仅本机存在、未入库、其依赖（Ollama/PaddleOCR 等）未在当前机器上重新验证；**当前已验证可用的只有**：`tools/ingest.mjs` 下游、`_pdf/` 里已有的转写与规则文件。操作化的流水线（含记账/溯源/重试）**尚未实现**，属 Task 4。（出处：提交 `ab7a4d1c2` 的 README「多角度识别」六步法；`_pdf/_transcribe-rules.md`）

| 阶段 | 做法 | 资源 | 状态 |
|---|---|---|---|
| 0 判型 | 先判断**电子版还是扫描件**：电子版有文字层，直接转文本，**不要跑 OCR**（公式会被降级成图像猜测） | `_tools/_pdfinfo.py`（逐页 `textchars` / `images`） | 工具存在（本机，未入库） |
| 1 拆页 | 200 DPI 全页通读建立结构；拿不准的局部 400–500 DPI 重渲；超过约 500 DPI 反而糊 | `_tools/_pdfrender.py` | 同上 |
| 2 识别 | **不信单一来源**：AI 看图 + 本地视觉模型 + PP-OCR 三路交叉；PP-OCR 可靠给「词」，**符号不可信**；字典第一行空行是 CTC blank（映射 `chars[class]`） | `_tools/vlm.py`、`_tools/ppocr.py` | 手工可用；**无哈希/缓存/重试/页级溯源** |
| 3 交叉验证 | 三路一致 = 高可信；**不一致 = 必须人工核对**；用语义约束反推、前后文比对 | — | 手工 |
| 4 存疑清单 | 转写稿末尾附「存疑」表，**不得把识别结果直接当定稿**；核对结果写回字迹档案（识别错误向常见符号塌缩，对不常见符号提高怀疑） | `_pdf/_transcribe-rules.md`（手写笔记转写规则） | 手工 |
| 5 结构化 | 拆成节点/边候选；证明写进**边**；落 `_inbox/*.md` | `_inbox/_模板.md`、`tools/ingest.mjs`（人核验后才跑） | 已实现（下游） |

**实际做过的是什么（交接单 `B:\MathGalaxy-archive\HANDOFF-2026-11-23.md` §10，比 README 的三路法更诚实）**：对手写群表示讲义，PP-OCR 基本零输出、本地 Qwen-VL 不可用，实际是**AI 直接读图 + 局部放大 + 语义交叉验证**；页面渲染图在 `_audit/group-rep/pages/<日期>/pNNN.png`，转写稿在 `_audit/group-rep/transcript/*.md`，存疑清单 `uncertainties-A/B.md`；订正与英文对齐脚本在 `_audit/group-rep/`（`apply-corrections.mjs`、`sync-en-corrections.mjs`、`fix-en-align*.mjs`、`add-character-theory.mjs`）。**不要声称跑过三路 OCR**；README 的三路法是方法设计，不是每次都实际可行。

**未能在仓库里找回的记录（明说，不假装有）**：此前用 **DeepSeek 做过「PDF 转写终稿订正」** 且成功，但本次**没有找到该次的提示词、脚本或结果记录**（对 `_audit/`、`_pdf/_vlm_logs`、`_pdf/_transcribe-rules.md`、`_tools/` 全文检索 `deepseek` 无命中；`docs/archive/` 无命中；只有 `docs/llm-pipeline.md`、`AGENTS.md` 以一句话提及先例。上面 `_audit/group-rep/apply-corrections.mjs` 等脚本是否就是该次订正的一部分**未核实**）。**该记录的找回与实现留给 Task 4**（开工时向用户索取/确认来源）；**不要凭印象重建提示词**，并先做小样本评估（官方文档称 `deepseek-flash` 接受图片输入，**转写质量未验证**）。

## 4. 可追溯字段（Task 4 的结果库记录须带；已设计，**未实现**）

文档实际**标题、作者、版本**；**文档哈希**（`docHash`）；**页与区域**引用；**原书定理编号**；**原始转写**；**订正后转写**；**订正历史**；来源归属；**agent 补写内容**与原文内容分开标记。方法与版本：`method`（`ocr|vlm|llm-text|manual`）、`methodVersion`、`promptVersion`、`stage`、`status`。

## 5. 规则

- ⛔ 不悄悄补造看不清的数学、缺失的证明或引用；看不清 → `[?]` 并进存疑清单。
- 订正教材的明显错误时**保留原始证据**（原始转写与页引用不得覆盖）。
- 不改变不是你的内容：用户手写笔记与第三方教材分别标注；`refs` 只写真实文献，讲义页/PDF 页进 `_audit`。
- 只发**公开**数学内容给外部模型；**私人笔记/未公开讲义是否可发需先问用户**；不上传 `20261117` 目录。
- 并入图之前必须走 [content-add](content-add.md) 并满足 [content-quality.md](content-quality.md)（尤其存在性、定义引用、证明归属、出处）。

## 6. 受保护资产

`_pdf/`（含手写原件 167 MB）**不删、不入 git、不发布**（不进 `dist`）；`_tools/` 里的识别脚本不删。

## 7. 验收与完成条件（对一次 PDF 摄取）

- 文档已登记（标题/作者/版本/哈希）；每个候选可追溯到页与区域；原始与订正转写并存；存疑清单已由人核对或明确留存。
- 候选已通过 [audit](audit.md) 的数学审计并按 content-add 并入；`git status` 无 `_pdf` 内容被意外跟踪。
- STATUS 已更新；临时物清理。

## 8. 失败与升级

识别不可靠 → 回到人工核对；不确定的数学 → `UNCERTAIN`；超出范围/预算 → 先请示；**不要声称未实现的能力可用**。
