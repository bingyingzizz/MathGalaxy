## 二、检查项（按实测优先级）

### A. 公式内混入中文标点或文字 ★★★ 146 条，最严重

**实测 146 条公式命中**，例如 `01-zfc-axioms.js`：

```latex
\forall F [ ( \forall X \in F, X \ne \emptyset ) \to \exists f ( f 是函数 ∧ ...
X \in \mathcal{A} \iff X 的每个有限子集都属于 \mathcal{A}
S = \{ J \in \mathcal{P}(I) : J 是归纳集 \}
P \ne \emptyset ∧ ( \forall C \subseteq P, C 是链 \to \exists u \in P, ...
```

问题分类：

| 子类 | 例子 | 应为 |
|---|---|---|
| 中文词语进了公式 | `f 是函数`、`X 的每个有限子集都属于` | 移出公式，或包 `\text{}` |
| 全角逗号 `，` | `… , X \ne \emptyset）` | 半角 `,` |
| 全角空格 `　` | `a_j \ge 0，E_j` | `\quad` / `\;` / 半角空格 |
| 全角括号 `（）` | `（无序对）` | 半角 `(` `)` 或移出 |

**判定**：数学公式里出现中文，**KaTeX 会把它当普通字符排**，字形、间距都不对。
**例外**：`\text{中文}` 是**允许**的（KaTeX 支持），检查时要排除 `\text{…}` 内部。

---

### B. 公式内 vs 正文：两套记号

**现状拆解**（这是关键区分）：

| | 公式内 | 正文 | 判定 |
|---|---|---|---|
| `∈` / `\in` | `\in` ×334 | `∈` ×193 | ⚠️ 两套并存 |
| `⟹` / `\implies` | `\implies` ×43 | `⟹` ×146 | ⚠️ 两套并存 |
| `⊆` / `\subseteq` | `\subseteq` ×85 | `⊆` ×138 | ⚠️ 两套并存 |
| `⟺` / `\iff` | `\iff` ×38 | `⟺` ×67 | ⚠️ 两套并存 |
| `≤` / `\le` | `\le` ×229 | `≤` ×54 | ⚠️ 见 C 项 |
| `μ` / `\mu` | `\mu` ×476 | `μ` ×362 | ⚠️ 两套并存 |
| `σ` / `\sigma` | `\sigma` ×4 | `σ` ×180 | ⚠️ **正文远多于公式** |
| `∀` / `\forall` | `\forall` ×84 | `∀` ×13 | 少量 |
| `↔` | `↔` ×8（**公式内的残留**） | — | 应改 `\leftrightarrow` |

**关键判断**：

> **正文里用 Unicode 符号，不一定是错的。**
> 写「设 A ∈ B」比写「设 $A \in B$」更易读、更少噪音。
> 但**同一个符号必须在全库统一**——不能一处写 `∈`、一处写 `$\\in$` 指同一件事。

**处理原则**：
1. **公式内** → 一律 LaTeX 命令（已基本达成）
2. **正文** → 择一，然后全库统一：
   - 方案甲：正文也用 `$…$` 行内公式（一致性最好，但正文噪音多）
   - 方案乙：正文用 Unicode 符号（可读性好，但需接受与公式的字形微差）
   - **建议乙**：正文的 Unicode 符号是**有意的可读性选择**，保留即可；只需把**漏改**的挑出来
3. 判据：**同一概念在两处写法不同 = 必改**；**正文统一用 Unicode = 可保留**

### C. 不等号：Unicode 变体 + 命令并存 ★最隐蔽

- `≤`（U+2264）与 `⩽`（U+2A7D）**是两个不同字符**，字形相似
- LaTeX 侧同理：`\le` 与 `\leqslant` 字形不同

**实测**：`\le` ×229、`\leqslant` **×0**；正文 `≤` ×54、`≥` ×31。

⇒ **约定：统一用 `\le` / `\ge`**（字形 ≤ ≥）。全库 229 次已在用 `\le`，改 85 处残留比改 229 处划算。

### D. LaTeX 语法与 KaTeX 支持范围

| 检查项 | 实测结果 |
|---|---|
| **KaTeX 不支持的宏** | ✅ **干净**（`\begin{}` `\label` `\ref` `\newcommand` 全无） |
| 命令大小写 | ⚠️ 注意 `\mathcal` 在源里写作 `\\mathcal`（JS 转义），**渲染层是 `\mathcal`，正常** |
| 花括号转义 | 源里 `\\{` `\\}` → 渲染为 `\{` `\}`，**KaTeX 正确识别为集合分隔符**（已验证） |
| 字形分组 | `\varphi`(φ) vs `\phi`(ϕ)；`\emptyset`(Ø) vs `\varnothing`(∅) —— **两套字形，需择一** |

> 💡 KaTeX 命令集**小于** LaTeX。若用了不支持的宏，`throwOnError:false` 会**静默显示红字**，不报错。

### E. 上下标：Unicode 与 LaTeX

**实测**：公式内 **0 / 0（已清空）**；**正文仍剩 下标 ×331、上标 ×61**。

**由于已接入 KaTeX**：正文的 Unicode 上下标（`Eᵣ`）与公式里 KaTeX 排的下标，**基线、字号都不一致**。

⇒ **约定**：
- **公式内**：一律 `_` / `^`（已达成）
- **正文**：上下标建议改行内公式 `$E_r$` / `$f_n$`；若坚持 Unicode，**至少不能与公式内的写法混用于同一符号**

### F. 符号语义一致性（星图特有）★需人工

| 检查项 | 说明 |
|---|---|
| **未定义就使用** | 符号首次出现处应有定义，或指向定义节点的 `definition` 边 |
| **同一符号两义** | 例：`μ` 同时表示测度与指数因子；`σ` 同时表示 σ-代数与标准差 |
| **同一概念两符号** | 例：测度空间写 `(X, 𝒜, μ)` 还是 `(X, ℳ, μ)` |
| **跨星团冲突** | `\mu` 在「测度」与「积分」星团含义应一致 |
| **边与节点对齐** | 边的 `proof` 里用的符号，必须与两端节点 `statement` 一致 |

> ⭐ F 项是**星图特有**：星图是**图谱**（节点 + 边），不检查的话，
> 同一符号会在不同节点/边的 proof 里悄悄漂移。

## 四、怎么查（可脚本化）

仓库**刻意没有 Node/npm 依赖**，所以不引入 linter，用本机已有工具一次性扫描。

### 4.1 ⚠️ 统计必须区分「公式内」与「正文」

**这是本清单编写时踩过的坑**：直接对整个 `.js` 文件跑正则统计会**把 JS 源码也数进去**，
得出虚高的数字（我第一次统计得到"1268 条公式含中文"是错的，实际 146 条）。

**正确方法**：**先取单引号字符串字面量，再在字符串内部匹配 `$$…$$` / `$…$`**。

```powershell
$files = Get-ChildItem 'src\data\packs' -Filter *.js
$blocks = @(); $inlines = @()
foreach ($f in $files) {
  $t = Get-Content $f.FullName -Raw -Encoding UTF8
  foreach ($s in [regex]::Matches($t, "'([^'\\]|\\.)*'")) {      # ① 先圈定字符串
    $v = $s.Value
    foreach ($m in [regex]::Matches($v, '(?s)\$\$(.+?)\$\$')) { $blocks += $m.Groups[1].Value }
    foreach ($m in [regex]::Matches($v, '(?<!\$)\$([^$\n]+?)\$(?!\$)')) { $inlines += $m.Groups[1].Value }
  }
}
"块级 $($blocks.Count)  行内 $($inlines.Count)"   # 期望：1399 / 432
```

### 4.2 A 项：公式内中文

```powershell
$all = ($blocks + $inlines) -join ' '
$hit = @($blocks + $inlines | Where-Object { $_ -match '[\u4e00-\u9fff\uff0c\uff1b\uff1a\u3000]' })
"涉及公式数 = $($hit.Count)"        # 编写时为 146
$hit | Select-Object -First 10
```

### 4.3 正文残留（B/C/E 项）

```powershell
# 取字符串字面量后，先把公式挖掉，剩下的就是正文
$v = $s.Value -replace '(?s)\$\$.+?\$\$','' -replace '(?<!\$)\$[^$\n]+?\$(?!\$)',''
foreach ($c in '∈','⊆','⟹','⟺','≤','≥','μ','σ') { "$c x$(([regex]::Matches($v,[regex]::Escape($c))).Count)" }
```

### 4.4 D 项：KaTeX 不支持的宏

```powershell
Select-String -Path src\data\packs\*.js -Pattern '\\(begin|end|label|ref|eqref|newcommand)\b'
```

### 4.5 ⭐ 渲染层验证（**最可靠，必做**）

正则查不出 **KaTeX 的渲染错误**。真正的检查是渲染后截图看：

```bash
msedge.exe --headless=new --disable-gpu --hide-scrollbars \
  --virtual-time-budget=8000 --screenshot=out.png \
  --window-size=1600,900 file:///H:/MathGalaxy/index.html
```

再 `read_image` 亲眼确认。或在控制台数错误节点：

```js
document.querySelectorAll('.katex-error').length   // 应为 0
```

> KaTeX 用 `throwOnError:false`，**出错的公式不会让页面崩，只会静默变红**。
> 所以「页面能打开」≠「公式都对」。
